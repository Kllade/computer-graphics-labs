# Проектирование лабораторной №1

## 1. Отправная точка: шаблон преподавателя

Оставить предоставленный цикл кадра и `graphics::internal::Context` основой
приложения. Лабораторную реализовать через четыре точки входа:

| Функция | Ответственность |
|---|---|
| `initialize` | Создать геометрию, буферы, дескрипторы и pipeline |
| `update` | Построить ImGui-интерфейс и обновить параметры на CPU |
| `render` | Подготовить данные GPU и записать команды рисования |
| `shutdown` | Дождаться GPU и уничтожить ресурсы |

На macOS проверить поддерживаемый формат глубины и физический размер
framebuffer. Размер depth image и render area должен соответствовать swapchain.
Если resize в шаблоне не реализован, использовать фиксированное окно.

## 2. Предлагаемая структура

```text
source/main.cpp                 окно и цикл кадра шаблона
source/graphics_internal.*     инфраструктура Vulkan шаблона
source/icosahedron.hpp/.cpp     геометрия фигуры и цвета вершин
source/math.hpp                векторы и матрицы
source/scene.hpp                параметры объекта, камера, анимация, M/V/P
source/graphics.hpp/.cpp        создание буфера и загрузка SPIR-V
source/application.cpp          ресурсы, интерфейс и команды лабораторной
shaders/icosahedron.vert        положение и цвет вершины
shaders/icosahedron.frag        цвет фрагмента; при необходимости подсветка
```

Геометрия будет строиться кодом. Отдельный файл `icosahedron.cpp` нужен,
чтобы форму фигуры можно было изучить независимо от Vulkan и интерфейса.
Функции математики также не должны зависеть от Vulkan.

## 3. Геометрия икосаэдра

Использовать золотое сечение `φ = (1 + sqrt(5)) / 2` и три группы точек:

```text
(±1, ±φ, 0), (0, ±1, ±φ), (±φ, 0, ±1)
```

Получаются 12 вершин. Нормализовать их до единичного радиуса описанной сферы.
Грани задать таблицей из 20 треугольников: три индекса на строку, 60 значений
`uint16_t`. Порядок обхода граней направить наружу.

Вершина хранит позицию и RGB. Для дополнительного задания 5 выбрать формулу
`vertexColor = 0.5 * (localPosition + 1)`: компоненты лежат в `[0,1]`.

Геометрия определяет форму. Матрица модели задаёт положение, поворот и размер
экземпляра этой формы — это разные данные.

## 4. Математические соглашения

Использовать векторы-столбцы и хранить матрицы по столбцам:

```text
M = T * Rz * Ry * Rx * S
V = lookAt(eye, target)
clip = P * V * M * vec4(position, 1)
```

Преобразования применяются справа налево. UI задаёт углы в градусах,
тригонометрические функции получают радианы. Для проверки порядка использовать
точку `(1,0,0)`: Scale=(2,1,1), Rz=90°, Translation=(3,0,0) дают `(3,2,0)`.

Начать с фиксированной камеры, смотрящей в центр сцены. Для перспективы
потребуются FOV, aspect, near и far; для ортографии — высота видимого объёма,
aspect, near и far. Предлагаемые near=0.1, far=100. Aspect рассчитывать по области
рисования, учитывая панель интерфейса. Глубина после деления на w — `[0,1]`;
для viewport с положительной высотой инвертировать Y в матрице проекции.

## 5. Первый объект и данные GPU

Сначала создать одну сетку, один UBO и один набор дескрипторов. Общий помощник
буфера объединит `VkBuffer`, VMA-аллокацию и отображённый указатель.

Предлагаемый uniform-блок:

| Поле | Назначение | Смещение |
|---|---|---|
| `mvp` | P*V*M для преобразования вершины | 0 |
| `model` | Мировая позиция для необязательной подсветки | 64 |
| `baseColor` | Цвет, выбранный пользователем | 128 |
| `useVertexColors` | Включение процедурных цветов | 144 |
| `enableShading` | Включение подсветки | 148 |
| `padding` | Выравнивание блока | 152 |

Размер блока std140 — 160 байт. В C++ использовать две Mat4, четыре float цвета,
два float-переключателя и два float padding. В GLSL — две mat4, vec4, два float,
vec2. Порядок и смещения проверить до запуска.

Набор дескрипторов указывает на UBO через `set=0, binding=0`.
Pipeline настроить для индексных треугольников, заливки, depth test/write LESS
и динамических viewport/scissor. Для простоты первоначально отключить culling.

## 6. Роли шейдеров

Vertex shader применяет MVP к позиции и передаёт цвет дальше:

```text
color = baseColor
если useVertexColors: color *= vertexColor
```

GPU интерполирует цвет по треугольнику. Fragment shader записывает его
в цветовое вложение; depth test определяет видимость фрагмента.

Подсветка — дополнительное удобство после обязательных заданий. Можно вычислить
плоскую нормаль из производных мировой позиции и множитель яркости
`ambient + directional * abs(dot(normal, lightDirection))`. Направление фиксировано,
режим отключаемый. Это простая двусторонняя подсветка, не полная модель освещения.

## 7. Анимация и взаимодействие

Хранить отдельную фазу времени у каждого объекта. При воспроизведении
увеличивать её на `deltaTime * speed`, при паузе сохранять. При долгом кадре
ограничивать шаг времени, например 0.1 секунды.

Предлагаемая пространственная траектория:

```text
offset = (R*sin(t), H*sin(2t), 0.6*R*(cos(t)-1))
```

Она начинается в нуле и замкнута с периодом 2π. Добавлять смещение к позиции UI.
Одновременно вращать объект вокруг трёх осей. Если углы приводятся по модулю
360°, сначала учитывать скорость соответствующей оси, затем приводить угол.

В ImGui последовательно добавить проекцию, Position/Rotation/Scale,
Play/Pause/Rewind, Speed/Radius/Height/Spin и ColorEdit. Отдельная галочка
процедурного цвета поможет проверить умножение цветов.

Если добавляется орбитальное управление камерой: горизонтальный drag уменьшает
yaw, вертикальный увеличивает pitch; pitch ограничить, например ±80°.
Колесо изменяет расстояние в перспективе и высоту объёма в ортографии.

## 8. Несколько объектов

После завершения заданий 1–5 расширить сцену до трёх экземпляров. Это выбранное
для демонстрации число; условие требует больше одного объекта.
Оставить одну сетку и один pipeline. Для каждого экземпляра создать своё
CPU-состояние, UBO и `VkDescriptorSet`. Общий индекс связывает три массива:

```text
objects[i] -> uniformBuffers[i] <- descriptorSets[i]
```

Перед каждым draw привязывать соответствующий set в слот 0. Это несколько
экземпляров набора, использующих один layout. Camera/Projection общие,
трансформации, цвет и время анимации индивидуальны. Выбор объекта в UI
переключает редактируемые настройки, не останавливая другие анимации.

## 9. Кадр и время жизни ресурсов

`update` меняет CPU-состояние. `prepare()` из шаблона ждёт fence.
После этого `render` может записать UBO, начать command buffer и render pass,
очистить цвет/глубину, задать viewport, привязать pipeline и buffers,
выполнить bind set + draw для каждого объекта и завершить запись.
Шаблон затем рисует ImGui, отправляет команды и показывает изображение.

При завершении дождаться GPU и освободить ресурсы. Частичная ошибка создания
также должна освобождать уже созданные ресурсы. Проверку выполнять обычным запуском: пройти UI-сценарии и посмотреть
сообщения validation layers. Автоматические тесты в проект не включать.
