# Лабораторная №1 — правильный икосаэдр

Номер в списке: **23**. При 12 вариантах: `((23 - 1) % 12) + 1 = 11`.
Реализован вариант 11 и дополнительные задания **1–6**, то есть объём на оценку **5**.
Итоговую оценку определяет преподаватель с учётом защиты и срока сдачи.

## Запуск

В VS Code откройте папку репозитория целиком. Переносимые команды сборки приведены
в README-macOS.md. Следующие задачи доступны в локальной конфигурации автора
(личная папка .vscode не публикуется):

- `Cmd+Shift+B` — конфигурация CMake, компиляция шейдеров и приложения.
- `Terminal → Run Task → Vulkan: run` — сборка и запуск.
- `F5` — запуск с отладчиком CodeLLDB.

Из терминала:

```bash
cd computer-graphics-labs
bash run-macos.sh
```

Окно фиксированного размера 1280×720; поддержка изменения размеров в исходном
шаблоне не завершена. На Retina используются физические размеры swapchain.
Интерфейс на английском. При нехватке высоты панель прокручивается колесом мыши.

## Что показать преподавателю

| Требование | Как проверить |
|---|---|
| Правильный икосаэдр | На экране 20 треугольных граней; исходная сетка содержит 12 вершин и 30 рёбер |
| 1. Две проекции | Переключить Perspective / Ortho, изменить Field of view / Ortho height |
| 2. Аффинные преобразования | Изменить Position, Rotation и Scale отдельно по X, Y, Z |
| 3. Сложная траектория | Play, затем Pause; настроить Speed, Radius, Height и Spin; Rewind возвращает начало |
| 4. Цвет фигуры | Нажать цветной квадрат Tint и выбрать цвет; для чистого цвета отключить Procedural vertex colors |
| 6. Несколько объектов | На сцене три икосаэдра; выбрать Object 1/2/3 и изменить только его цвет, трансформацию или анимацию |
| 5. Цвета вершин | Включить Procedural vertex colors, менять Tint: выбранный цвет умножается на цвет каждой вершины |

Object выбирает объект для редактирования. Position, Rotation, Scale, цвет и анимация
принадлежат выбранному объекту. Проекция и камера общие. Play/Pause воздействует
только на выбранный объект; анимации остальных продолжаются независимо.

Facet shading добавляет простое освещение, чтобы лучше различать грани. Его можно
отключить и увидеть непосредственно произведение цветов без влияния освещения.
Камера управляется перетаскиванием в области сцены и колесом мыши или через Camera.
Reset scene восстанавливает все исходные параметры. Камера не изменяет матрицу модели.

## Как устроено

### Геометрия

Начальные координаты — перестановки `(±1, ±φ, 0)`, `(0, ±1, ±φ)`,
`(±φ, 0, ±1)`, где `φ = (1 + sqrt(5)) / 2`. Они нормализованы до единичного
радиуса описанной сферы. Индексный буфер содержит 60 индексов — 20 треугольников.
Цвет вершины вычисляется из локальной позиции: `C = 0.5 * (position + 1)`.
До изменения масштаба все рёбра имеют одинаковую длину. Неравномерный Scale
намеренно деформирует исходный правильный многогранник.

### Матрицы

Используются столбцовые векторы, матрицы хранятся по столбцам:

```text
model = Translation * RotationZ * RotationY * RotationX * Scale
clip = Projection * View * model * vec4(position, 1)
```

Перспектива уменьшает удалённые объекты; ортографическая проекция сохраняет
масштаб независимо от глубины. Глубина после деления на W соответствует диапазону
Vulkan `[0,1]`, знак Y в проекции инвертирован. Near = 0.1, far = 100.
Пропорции проекции вычисляются по области сцены справа от панели.

### Анимация

`t` — накапливаемое время анимации, увеличивается на `dt * Speed` только при Play.
Пауза сохраняет время; продолжение не перескакивает на текущее системное время.
Движение добавляется к пользовательской позиции:

```text
x = Radius * sin(t)
y = Height * sin(2t)
z = 0.6 * Radius * (cos(t) - 1)
```

Одновременно добавляется вращение вокруг трёх осей. Spin задаёт базовую скорость
вращения; Speed масштабирует всю анимацию. Radius и Height меняют форму траектории.
Изменение этих параметров при паузе обновляет положение на текущей фазе.

### Vulkan

Вершины и индексы находятся в буферах VMA. У каждого из трёх объектов свой UBO: model, MVP,
цвет и настройки шейдера. Каждый UBO связан с собственным `VkDescriptorSet`
(binding 0). Схема набора (VkDescriptorSetLayout) у всех общая. Обновление UBO выполняется в render() **после ожидания fence**
в graphics::internal::prepare(), чтобы CPU не перезаписывал данные занятого GPU.

Создаются графический конвейер, vertex input, depth test и render pass из шаблона.
Кадр очищается, записываются команды привязки буферов/дескриптора/конвейера и
`vkCmdDrawIndexed`. После фигуры шаблон рисует ImGui. Все созданные ресурсы
приложения освобождаются в shutdown(), в том числе при частичной ошибке initialize().

### Дополнение 6: что важно понять

Набор дескрипторов не хранит геометрию или сами матрицы. Он указывает шейдеру,
из какого буфера читать данные. Здесь используются **три разных набора**,
каждый ссылается на свой UBO. Геометрия, конвейер и шейдеры общие.

Структура `Object` содержит только три поля: состояние, uniformBuffer, descriptorSet.
Объекты хранятся в обычном `std::array<Object, 3>`. Наследования и менеджеров ресурсов нет.

Порядок чтения кода в `source/application.cpp`:

1. `Object` — что хранится для каждого икосаэдра.
2. `resetScene()` — исходные позиции и цвета трёх объектов.
3. `initialize()` — пул на три набора; цикл создания UBO и привязки binding 0.
4. `ui()` и `update()` — выбор объекта и независимое обновление анимаций.
5. `render()` — сначала заполнение трёх UBO, затем цикл `bind descriptor set → draw`.
6. `shutdown()` — уничтожение пула дескрипторов и трёх UBO.

В каждом вызове `vkCmdBindDescriptorSets` параметр firstSet равен 0:
мы меняем набор в одном слоте конвейера, а не добавляем новые binding.

Для демонстрации выберите центральный объект, измените его цвет и нажмите Play.
Боковые объекты должны остаться неизменными. Переключение проекции влияет на всех.

## Файлы

- `source/application.cpp` — Vulkan-ресурсы, интерфейс, обновление и команды рисования.
- `source/scene.hpp` — геометрия, математика и параметры сцены; без сторонней библиотеки матриц.
- `shaders/icosahedron.vert` — преобразование координат и цвет вершины.
- `shaders/icosahedron.frag` — итоговый цвет и необязательное освещение граней.
- `tests/scene_tests.cpp` — проверка геометрии и математических свойств.
- `source/graphics_internal.cpp` — инфраструктура из стартового шаблона с macOS-правками.

## Проверка

```bash
ctest --test-dir build-macos --output-on-failure
CG_LAB_SMOKE=1 bash run-macos.sh
```

Тест геометрии проверяет равные рёбра, принадлежность каждого ребра двум граням,
ориентацию граней, нормировку, цвета. Тест матриц проверяет границы глубины,
перспективное уменьшение, ортографическую инвариантность и порядок преобразований.
Тест анимации проверяет скорость, паузу и замкнутость траектории.

CG_LAB_SMOKE — автоматический прогон 180 кадров: переключаются обе проекции,
цвета, анимация, у трёх объектов разные масштабы, цвета и скорости; центральный остаётся на паузе; затем приложение закрывается
обычным путём с освобождением ресурсов. Без переменной приложение работает интерактивно.
